Help

An overview of how to configure and use matrix³.

You can use this extension to control the permissions of websites. For example, enabling sandbox features, disabling scripts, stylesheets, and fonts, or choosing which third parties can provide subresources.

The first thing you probably want to do is choose a default policy in the Options panel.

Report

This is the primary panel for interacting with matrix³. It lets you control the permissions of the active website. If the page embeds frames from other origins, each origin appears as a tab above the table.

Session and Dynamic Rules

Toggling a checkbox in the Report panel creates a temporary session rule that lasts until you close the browser. Remember to reload the page after making any changes.

If you want to keep the rule, you can Commit it, creating a dynamic rule that persists across browser restarts.

  • Commit: Save the temporary session rule as a persistent dynamic rule.
  • Uncommit: Demote a dynamic rule back to a temporary session rule.
  • Abandon: Discard any session changes and restore the saved dynamic rule.
  • Reset: Remove all session and dynamic rules for the host.
  • Disable: Temporarily disable matrix³ on the active tab.
  • Reload: Reload the tab to apply rule changes.

Violations

Blocked resources and actions are highlighted in orange. Enable the needed checkboxes, then click Reload to test. When you are happy with the settings, you can Commit them to make them permanent.

Sandbox Directives

Enabling the sandbox runs the document in an isolated origin and blocks scripts, forms, popups, downloads, and navigations. You can make exceptions, these options will only be visible if the sandbox is enabled.

Please note that cookies will not work when sandboxed without Allow Same Origin.

Server Suggested Policy

Shows the policy recommended by the server for the current origin. Accept replaces your selection with the server's policy; Merge adds the server's sources to your existing selection. This is entirely optional.

Note that nonces and hashes in a server policy are translated to 'unsafe-inline' so inline resources continue to work across reloads.

Rules

The Rules panel lists all active dynamic rules, session rules, and static rulesets across all websites. Use Filter to search by host or directive. You can select multiple rules and Remove or Commit them in one operation.

The Reset button will remove all saved rules after confirmation, allowing you to start fresh. You should backup your settings from the Export panel first, just in case.

Groups

If you find yourself allowing or denying the same set of origins regularly, you can create a Group that will perform those actions for you in one click.

If you browse in a strict mode, this can streamline making sites work that use embedded content like videos, payments, widgets, or captchas.

You create your groups in the Groups panel, and then select one in the Report panel. Click Apply to update the current host's session rules.

Each checkbox cycles through three states. A check enables the directive, a minus clears it, and unchecked leaves it unchanged.

Ignore

The Ignore group is special: any directives checked in this group are hidden from violation reports. If there is something you will never enable, and don't want it cluttering up the report, you can add it here.

Exclusions

If default-src is checked in the Ignore group, all violations for this origin will be ignored. If you want everything to be ignored except for certain types, you can check default-src and set the exclusions to minus.

Options

Default Policy Strictness

Sets the baseline policy in the Options panel for sites without custom rules:

  • Permissive: Nothing is blocked by default; restrict sites individually in the Report panel.
  • First Party: Allows first-party resources and third-party images, styles, and fonts. Blocks third-party scripts.
  • Sandbox + Scripts: Sandboxes every document in an isolated origin, allowing only scripts and forms. Cookies require Allow Same Origin.
  • Sandbox: Sandboxes every document with no exceptions; only static content works by default.
  • Strict: Blocks everything except first-party styles and images.

Always Show Advanced Directives

Rarely used directives and advanced sandbox flags are hidden unless checked or triggered by a violation. This is to reduce unnecessary clutter in reports. Enable this to always show them.

Show Icon Badges

Displays a red ! badge on the toolbar icon when the active tab reports a CSP violation.

Confirm Actions

Asks for confirmation before destructive actions such as resetting rules or deleting groups.

Unregister Service Workers on Reset

Service workers can complicate policy enforcement, so it's a good idea to unregister them if you're tightening a policy. This option unregisters service workers for the selected host when clicking Reset, preventing cached workers from causing confusing results.

Default Scope

You can choose whether to group rules by registrable Domain (e.g., *.example.com) or by exact Host (e.g., sub.example.com).

It's much easier to manage rules by domain, but some users might prefer control over individual hosts within a domain. If you're not sure, stick with Domain.

Allow Private Domains

When using Domain scope, enable this to treat shared hosting suffixes (such as github.io or s3.amazonaws.com) as separate domains so each project or bucket gets its own rules.

Export

In the Export panel, Download allows you to backup your rules and settings to a JSON file, and Import restores them from a backup.

Sync

When signed into Chrome, Push and Pull synchronize your settings across devices. Click Push to save your changes to cloud storage, and Pull to fetch any updates saved from another device.

Note that session (temporary) rules always remain local.
